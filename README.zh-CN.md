## 研究问题

当事件记录不完整、时间戳存在并列时，电商漏斗还能支持哪些判断？

以事件质量与可观察购买路径为主线，设备比较为辅助。未记录购买不等于真实流失；记录异常不等于已确认埋点故障。数据为固定版本的第三方GA4扁平化副本，未与Google原始表或后台订单逐行核对。

覆盖2020-11-01至2021-01-31，共92天、4,295,584条事件记录、360,129个可识别会话。

## 结果与解释

| 会话组 | 会话数 | 有购买记录 | 严格完整路径 | 严格路径不完整占购买会话 |
|---|---:|---:|---:|---:|
| 全部 | 360,129 | 4,848 | 2,778 | 42.70% |
| 涉及固定异常日期 | 61,771 | 815 | 0 | 100.00% |
| 未涉及固定异常日期 | 298,358 | 4,033 | 2,778 | 31.12% |

固定日期为2020年11月2–15日、11月21–24日。会话中任意事件触及即属于“涉及”组。先根据完整历史构建路径和标记，再按会话首次观察日期筛选。未涉及组不是清洗后的正常样本。

1. **路径缺口不能直接解释为流失。** 涉及组仍有815个购买会话，却没有完整四步路径。
2. **18天异常不能解释全部问题。** 未涉及组仍有1255个购买会话缺少完整严格路径，占31.12%。
3. **时间并列只能解释少量缺口。** 严格完整2778个；允许同刻兼容后2834个，增加56个，不代表实际按该顺序发生。
4. **设备比较只作描述。** 移动端和桌面端购买记录会话率约1.39%和1.32%，不能据此判断界面优劣。

全部4848个购买会话分为：严格完整2778、仅同刻兼容56、四阶段齐全但不符合顺序14、缺少前置阶段2000。全部92天和不利结果保留，未为结果好看调整窗口或规则。

## SQL 能力体现

- **粒度与复合键：** 保留源事件行，以用户伪标识＋会话编号定义会话，跨午夜不拆开；无效身份单独审计。
- **CTE与不等式连接：** 找每一步最早的、满足上一阶段之后的事件，允许阶段重复，避免只比较各阶段全局首次时间造成漏判。
- **条件聚合与相关子查询：** 用FILTER、CASE、EXISTS表达阶段出现、购买前置事件和24小时后续购买记录。
- **分析中间表：** 固定异常日期、完整历史会话标记、互斥路径分类、日×设备覆盖表。
- **分母与日历骨架：** NULLIF保留无分母的缺失值；区分“当天无任何记录”和“有记录但某事件为零”。
- **口径测试：** 覆盖重复阶段、同刻事件、跨日会话、筛选不截断路径、空筛选、分类对账和随访截尾。

主要计算在SQL中，Python负责组织运行、导出和界面。部分参数化SQL在dashboard/data.py，审计导出SQL在scripts/audit.py。不把未使用的窗口函数、dbt、Spark、BigQuery或生产数据平台列为本项目能力。

## 分析流程与看板

先审计覆盖、身份、会话质量、交易字段和时间并列，再固定后续口径。看板有三页：

- 事件覆盖与质量：按事件发生日期展示，18天固定标记不随筛选重定义。
- 观察到的购买路径：三组对照、四类购买会话、严格与同刻兼容路径、观察边界。
- 设备辅助比较：数量和比例同时展示，保留质量诊断和不完整周提示。

24小时后续观察以每个伪用户首次结账为锚点，属于独立用户层分析。尾部随访不足者单列，不算失败；跨会话购买不等于同一购物车被挽回。

## 本地运行

本审核包不含虚拟环境、原始数据和数据库；现有ga4-local-dashboard目录保持原样，仍可使用原来的启动入口。

首次运行本包：在项目根目录打开终端，推荐Python 3.12（已验证版本）：

```powershell
python scripts/setup_local.py
.venv/Scripts/python -m streamlit run app.py
```

Windows也可依次双击Setup.cmd、Start_dashboard.cmd。打开http://127.0.0.1:8501，保持启动进程运行，Ctrl+C结束。若本看板已在该端口运行，直接打开地址即可。macOS/Linux改用.venv/bin/python，未在本轮跨平台验证。

首次安装和下载需要普通网络、约274MB源数据和额外环境/数据库空间，建议预留2GB以上。无需Google Cloud、计费项目或凭据。初始化后使用本地数据，服务只绑定本机，关闭Streamlit使用统计。

完整重建和测试命令见[英文README](README.md#rebuild-and-validate)。历史审计HTML保留，构建命令重建审计CSV/JSON及本轮分析HTML。实现阶段14项测试通过，独立目录重建36份结果逐字节一致；具体边界见[验证记录](reports/verification.json)。

## 局限

- 固定文件哈希证明输入版本一致，不能证明与Google原表完整对应；上游notebook与schema不完全一致。
- 伪用户不等于自然人，会话路径不保证同一商品或购物车，购买事件不等于核实过的订单。
- 缺少购买记录可能涉及真实未购、记录缺口、导出、脱敏、身份变化或观察窗口，当前数据无法分离。
- 同刻兼容只给出观察序列的可能数量，不是置信区间、真实行为边界或确定顺序；逐步比例因分母变化不能作为区间上下界。
- 收入、客单价、品类和当前会话渠道归因因字段/质量限制暂停，没有用替代字段强行产出。
- 没有显著性检验、因果UX结论、生产部署或业务提升证明。
